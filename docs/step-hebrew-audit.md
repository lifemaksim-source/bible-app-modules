# STEP Bible TAHOT — проверка еврейского первоисточника

**Что берём:** готовую пословную разметку TAHOT от [STEP Bible / Tyndale House Cambridge](https://github.com/STEPBible/STEPBible-Data) на основе Ленинградского кодекса и Open Scriptures; **не генерируем библейские слова ИИ**. Четыре исходных файла Ветхого Завета (Gen–Deu, Jos–Est, Job–Sng, Isa–Mal) перечислены с Git blob SHA и размерами в `sources-step-hebrew.json`.

**Что проверяем в этом PR:** только первый файл **Бытие–Второзаконие**. Другие три файла перечислены, но помечены `audit:false`: до отдельной проверки они **не считаются проверенными**.

## Почему импорт без морфемного «угадывания»

Исходные записи TAHOT могут содержать несколько морфем в одной строке, разделённых `/`, и несколько чтений (Ketiv/Qere) в полях `Meaning Variants`, `Spelling Variants` и `Ref & Type`. Набор TAHOT — не буквальная привязка к русскому тексту Синодального перевода.

Для знакомства с форматом изучен существующий парсер [openbible-io/step](https://github.com/openbible-io/step/blob/master/src/tat/tahot.ts) (CC BY 4.0). Он содержит алгоритм похожести строк при выравнивании альтернативных написаний. **Мы не используем этот эвристический алгоритм:** там, где нет однозначной морфологической связи, сохраняем исходные строки и варианты отдельно.

`tools/step-hebrew.mjs` читает TAHOT без изменения еврейских слов, морфологии, номеров Стронга, полей вариантов чтения и исходных меток. Книги проверяются по явно заданной группе Gen–Deu; адреса стихов не пересчитываются автоматически в русскую/английскую нумерацию. Строит только временную SQLite-базу со всей исходной информацией. **Это ещё не отображаемый подстрочник.**

Лицензия *исходного репозитория данных* STEP Bible — **CC BY 4.0**, обязательна атрибуция. Встречаются SWORD-пакеты THOT с **иными условиями**: не использовать их права вместо прав на конкретный исходный набор. Перед публичным релизом проверить права на все комбинируемые данные и отображаемые переводы.

## Запуск

```sh
npm ci
node --test tools/step-hebrew.test.mjs
node tools/step-hebrew.mjs --sqlite-smoke
```

Первый запуск должен проверить первоисточник по закреплённому SHA Git blob, число строк, пять книг, метки Ketiv/Qere и схему временного SQLite. После удачного реального прогона сюда нужно вписать проверенную SHA-256 и конкретную статистику, а также добавить SHA-256 в manifest.

Исходные файлы и тексты стихов **не коммитятся**, в логах только метаданные/счётчики. Нет автоматической публикации в `catalog.json`, Releases, APK или артефактах GitHub CI.

**Следующий этап:** проверить остальные три части TAHOT и реальные варианты нумерации; далее построить безопасный слой связи с приложением и отображать альтернативные чтения явно, без самостоятельного выбора «правильного» чтения.
