# Пять черновых MyBible SQLite из электронных EPUB Института перевода Библии

Дата: 21.10.2026. **Статус: реальные исходники прочитаны, пробные базы собраны и проверены, НЕ опубликованы.**

## Выполнено

GitHub Actions [#39630706196](https://github.com/lifemaksim-source/bible-app-modules/actions/runs/39630706196) скачал **пять реальных EPUB**, прочёл идентификаторы стихов OSIS, построил каждую SQLite **только во временной директории** и запустил `PRAGMA quick_check`. Отчёт содержит SHA-256 входного EPUB и пробной базы. Двоичные тексты не загружались в GitHub artifacts, Releases или APK.

Конвертер: [`tools/convert_ibt_epub.py`](../tools/convert_ibt_epub.py), тесты [`test_convert_ibt_epub.py`](../tools/test_convert_ibt_epub.py). Это не второй механизм скачивания в Bible App: результат в совместимой структуре MyBible `info`, `books`, `verses`, `stories`, `notes`.

| Язык | Код | Книг | Строк со стихами | Нераспознанных/пустых маркеров | Ссылок на примечания в исходнике |
|---|---|---:|---:|---:|---:|
| Табасаранский | `tab` | 37 | 14 020 | 83 | 12 562 |
| Лакский | `lbe` | 6 | **5 087** | **103** | 5 180 |
| Ингушский | `inh` | 6 | **3 623** | **4** | 2 228 |
| Гагаузский | `gag` | 31 | 9 830 | 14 | 9 456 |
| Дунганский | `dng` | 6 | 6 393 | 373 | 3 904 |

Конвертер берёт только стихи с исходными XML/HTML-якорями вида `Gen.1.1`, `_1Cor.8.2`. Он поддерживает обычные абзацы, поэтические строки `osis-l` и библейские нумерованные списки `osis-list > osis-item`, сохраняет книгу/главу/стих и исключает маркеры номеров и разделы примечаний издателя. Не создаёт несуществующих стихов, не угадывает номера по очереди, не меняет слова вручную. Нормализуются пробелы, ввод строго UTF-8 (ошибочное кодирование отклоняется). Для всех извлечённых стихов проводится **полная проверка обратного чтения SQLite** — номера и нормализованные строки должны в точности совпасть с исходными данными конвертера. Это доказывает сохранность после записи в базу, **но не полное соответствие всего текста EPUB**. Всего в EPUB обнаружено 33 330 ссылок на примечания; они исключены из текстов стихов, но сами примечания в пробные SQLite пока **не перенесены**.



### Зафиксированное исправление после сравнения структур HTML

В [GitHub Actions #39630706196](https://github.com/lifemaksim-source/bible-app-modules/actions/runs/39630706196) обнаружены и корректно извлечены **63 дополнительные стиховые строки**: 59 в ингушском (`Gen.10`, нумерованные списки родословий) и 4 в лакском. До этого внутри `<ol class="osis-list"><li class="osis-item...">` они оставались без текста. Книги, номера глав/стихов и другие три SQLite не изменились. Извлечение разрешено только для подтверждённых OSIS-списков внутри разделов Писания: обычные списки навигации/издательские комментарии не импортируются. Все пять баз прошли `PRAGMA quick_check` и точное сравнение строк SQLite со словарём извлечённых стихов.

*Это не подтверждение полного перевода:* пробные файлы по-прежнему создаются временно, их SHA-256 обновлены в [реестре](language-module-discovery.json), но двоичные файлы не публикуются.

### Почему ещё не готовы к распространению

1. **Осталось 577 пустых/неразобранных стиховых маркеров:** 83/103/4/14/373 соответственно. Это может быть особенностью верстки, объединением стихов, ненаполненным маркером или ошибкой извлечения. Нельзя заполнять их содержимое ИИ и объявлять полноту без сверки каждого типа пропуска.
2. **Контроль точности текста** относительно конкретного издательского EPUB ещё не завершён, особенно поэзия, параграфы, примечания, перекрёстные ссылки и смешанные стиховые диапазоны. Технически корректная SQLite не гарантирует буквальной сохранности текста.
3. **Права на распространение не подтверждены.** Электронные книги опубликованы Институтом перевода Библии, но автоматическое скачивание не даёт права распространять производную базу. `licenseStatus=not_cleared`.
4. **Android smoke отсутствует.** Для `tab`, `lbe`, `inh`, `gag`, `dng` пока нет публичных записей в `catalog.json`; исходные ZIP/EPUB не нужно класть в основной APK.
5. Некоторые книги отсутствуют в этих частичных изданиях — это нормально; навигация должна учитывать фактическое покрытие (см. [app PR #56](https://github.com/lifemaksim-source/bible-app/pull/56)).

## Минимальная проверка в приложении — без новой инфраструктуры

**Проверено на пяти реальных EPUB:** [GitHub Actions #39634738208](https://github.com/lifemaksim-source/bible-app-modules/actions/runs/39634738208) создал 5 приватных ZIP из тех же исходников, что используются в черновом конвертере. Для каждого проверил ровно один `IBT_<lang>.SQLite3` внутри ZIP, CRC архива, `PRAGMA quick_check` и совпадение количества книг/стиховых строк и кода языка. Результат **5/5**; файлы остались только на временном диске runner, в artifact попал только JSON-отчёт. Это контроль **формата ZIP и SQLite**, но не запуск приложения Android.

**Теперь конвертер умеет по явному запросу создать пять тестовых ZIP-файлов локально.** Это только для приватной инженерной проверки, не публикация и не APK.

```bash
# В клоне bible-app-modules: создаст IBT_<язык>_LOCAL_TEST_ONLY.zip
python3 tools/convert_ibt_epub.py --local-test-zips ./private-ibt-test
```

Затем в существующей Bible App на Android открыть «Библиотека → Импорт файла» и выбрать один ZIP. Реализованный ранее импортёр `src/library/install.native.ts` уже умеет распаковывать MyBible SQLite, другой загрузчик не нужен. Проверить **ингушский** (только 4 пустых маркера) и **гагаузский** (14) первыми, остальные — после. Изолированный app [PR #56](https://github.com/lifemaksim-source/bible-app/pull/56) исправляет навигацию по частичным книгам/главам и трёхбуквенные языковые коды; перед проверкой его нужно интегрировать с разрешения пользователя, а не напрямую в main.

Не добавлять `private-ibt-test/` в git, GitHub Actions artifacts, публичный реестр или Release; права на распространение этих изданий не согласованы. `--local-test-zips` **не используется** в CI, и без флага ZIP вообще не записываются.

**Важно для MVP:** перенос тысяч издательских сносок, разработка другого каталога, полное исправление 577 пустых маркеров любой ценой и отдельный сервер загрузки **не нужны для первой локальной проверки**. Их разумно оставить на будущее. Пустые маркеры не заполнять и не выдавать частичный текст за полное издание.

## Как повторить локальный черновой тест

```sh
python3 -m unittest discover -s tools -p test_probe_ibt_ebooks.py -v
python3 -m unittest discover -s tools -p test_convert_ibt_epub.py -v
python3 tools/convert_ibt_epub.py --report ibt-sqlite-drafts.json
```

В последней команде используются URL **с того же официального сайта** из `docs/language-module-discovery.json`. На диск записывается только JSON с метаданными: SQLite существует лишь во время проверки.
