# bible-app-modules

## Проверка сборки без публикации

`npm ci && npm test` — тесты разбора USFM и FB2.

В Actions → «Сборка модулей» → Run workflow выберите ветку и включите `dry`:

```sh
gh workflow run build.yml --ref codex/lopukhin-coverage -f dry=true
```

Отчёт появляется в аннотации «Отчёт» и сводке запуска. Файлы Release и
`catalog.json` не публикуются. Публикация дополнительно ограничена веткой `main`.
В итоговом отчёте проверьте покрытие Лопухина, отсутствие неверных ссылок и
«версия 1 (без изменений)» у web, bsb, asv, bbe, msb, xref и strong.

## Покрытие Лопухина

В опубликованной версии 1 предупреждение о десяти псалмах относилось к
52, 69, 97, 107, 116, 122, 133, 134, 135 и 145. Девять из них уже содержат
комментарий ко всей главе (`verse_number_from = 0`), который старый счётчик
не учитывал. Общая статья о псалмах 134 и 135 в версии 1 привязана только
к 135-му. Разбор заголовков поддерживает диапазоны и связывает общую статью
с обеими главами; вступления без стиховых якорей сохраняют номер своей главы.

Счётчик учитывает и общие, и постиховые толкования. Если глава действительно
не представлена, её номер явно перечисляется в отчёте. Оба конца каждого
диапазона сверяются с синодальной нумерацией; неверная ссылка останавливает
сборку Лопухина. Дополнительные FB2-body со сносками не разбираются как стихи:
например, id `n01-Gen_789` не означает Быт 1:789.

`catalog.json` обновляет бот в Actions. Не включайте его локальные изменения
в коммиты; сборщики остальных типов модулей при исправлении Лопухина не меняются.
